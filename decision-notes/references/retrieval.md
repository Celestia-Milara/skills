# Finding Applicable Decision History

Locate and assess records in this order:

1. Use the project's Agent entry point to find the actual notes location and applicable global constraints. Use subsystem documentation to locate current responsibilities, contracts, source code, tests, and related notes. A subsystem may span packages or repositories, and one note may relate to multiple subsystems.
2. Follow links, then search by question, mechanism, solution name, and constraint as needed. Include relevant failure evidence or candidate lessons linked from subsystem, change, or verification sources. A candidate does not have decision authority. The absence of a link, code, or matching name does not prove that there is no history. If no subsystem page exists, use available materials and the task topic; do not create an empty document in advance.
3. For decision records, start with the title, `Status`, `Scope`, and conclusion; read rationale, alternatives, and evidence when relevant. For candidates, check observations, evidence, applicability, and open causes in their owning source without imposing decision fields. Prefer effective decisions, then trace history by relevance. Search archived records when reconsidering an old option or when current guidance is insufficient. Trace supersession by scope; do not follow an arbitrary chain to its end.
4. Confirm the record's applicability and current facts. If the directory truly does not exist, continue; create it only when a record is first needed. A failed read or search with no matches does not prove there is no history.

A failed tool invocation is not an empty history. State access limits, continue independent work, and ask only for missing information that affects a necessary decision.

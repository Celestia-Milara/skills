### Worktree and simulator cleanup

1. Snapshot and audit. Record free space with the native platform tool. Run `scripts/worktree-audit.sh [-b <local-base-ref>] [repo-path]` where Bash is available, or the host adapter's Python audit on Windows. Both read paths from Git worktree metadata. The Bash table reports local size, age, merge/ref state, and tracked, untracked, and ignored content. It does not fetch or read PRs and transcripts; those columns stay unknown. Local tracking refs can be stale. A failed inspection remains unknown and returns a nonzero exit.
2. No bucket establishes deletion safety. `hold-wip` and `hold-local-content` retain local work; `review` and `review-unknown` still require evidence. Check current PR state through available read-only host tools when it matters. A closed PR is not proof of a merge. Cross-check pinned and active chats through the host's actual sidebar or chat tools (principle-prove-it-works).
3. Verify usage before deleting. Use workspace-scoped history and active-session evidence for each candidate. Delegate independent checks when useful and available; preserve the same scope and authority in each brief. A pinned chat can spawn arena or repro trees into sibling worktrees, so absence from the sidebar alone does not establish inactivity. Unknown activity remains unknown.
4. Establish deletion scope. A cleanup request covers only its stated targets. The Bash `DIRTY` column counts tracked, untracked, and ignored entries; none is proven throwaway content. Inspect the actual files. Preserve user work and unknown ownership unless deletion authority covers it. Clean, merged, and not-in-use are eligibility evidence, not permission. Reuse an existing decision covering the exact loss; ask only for missing scope and hold uncertain or active paths.
5. Remove only the authorized set. Resolve each absolute path and verify it belongs to the intended repository or named cleanup directory. Use `git worktree remove <path>` without force first. If it refuses, inspect the reason. Use force or recursive removal only when authorization covers every remaining file, including ignored content. Use the native shell and literal paths; do not expand an unchecked path into a recursive delete. Prune stale metadata only after checking it. Re-list worktrees and measure reclaimed space.
6. Treat simulators and caches as separate cleanup targets. Audit usage and state first. A worktree cleanup request does not authorize deleting simulator data, runtimes, application snapshots, or package caches. Run targeted native cleanup commands only within the requested scope. No keep instruction is not disposal permission; do not default to `delete all`.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** Native free-space measurements before and after, space reclaimed, the worktrees pruned, and a reason for each held back. Name missing activity or ownership evidence.
